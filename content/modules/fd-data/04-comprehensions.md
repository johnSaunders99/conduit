## 目標不是少寫幾行

商品來源送來 0 分、負數和正整數。本練習的價目清單只收正價，輸出時把分轉成兩位小數的顯示字串。原始金額仍用整數分來判斷，不因為畫面要顯示成金額就先轉成小數再過濾。用迴圈先驗證規則，再換寫法，你能看出兩份結果為什麼應該一樣。

## 語法速查

列表推導式（list comprehension）寫成 `[輸出 for 項目 in 來源 if 條件]`。讀的順序是右半邊先：從來源取一項，判斷條件，通過才算最左邊的輸出。沒有篩選時寫 `[輸出 for 項目 in 來源]`，來源每筆都會得到一個結果。要留原值就把輸出寫成原變數；要換欄位，輸出可以是算式或元組。

篩選（filter）決定留下哪筆，轉換（transform）決定留下的那筆長什麼樣。兩件事分開想：格式化不能讓無效價格變有效；如果無效價應當完全排除，就不該填成 0 假裝正常。這裡只改寫新列表，原列表和有效列的先後都保留。

## 用迴圈當對照

在 `C:\dev\conduit-lab\python-data` 存 `valid_prices.py`，執行 `py valid_prices.py`。以下是展示價格，不用格式化後的字串做金額運算。

```python
prices = [("K03", 0), ("K01", 125), ("K09", -5), ("K02", 125), ("K04", 99)]

by_loop = []
for sku, cents in prices:
    if cents > 0:
        by_loop.append((sku, f"{cents / 100:.2f}"))

by_rule = [(sku, f"{cents / 100:.2f}") for sku, cents in prices if cents > 0]
print(by_rule)
print("same:", by_loop == by_rule)
print("source rows:", len(prices))
```

結果依序是 K01 的 `1.25`、K02 的 `1.25`、K04 的 `0.99`。K01 和 K02 價格相同，但兩筆都有效；推導式沒有理由少留一筆。來源仍有 5 筆；比對回傳 `True` 只代表兩種寫法一致，還需要一筆手算的有效與無效樣本，才能確認兩種寫法沒一起犯同一個錯。

接著把需求改成「至少 100 分」，想清楚比較的是 100 分、不是顯示用的 1.00。加入 99 和 100 這一對邊界值，比只用 125 與 0 更能辨別 `>=` 和 `>`。如果後續要替無效價格記下「空值」「負數」等原因，就保留清楚的迴圈；[〈例外與隔離〉](#/lesson/fd-io-07)會把不合格列寫成另一份產物。

### 看形狀，再看規則

想像下游拿到 K01、K02，只知道商品代碼，不知道報表要顯示什麼。你可以只回傳代碼、回傳金額，或像本例回傳「代碼、顯示價」的元組；選哪個都只改左邊輸出，右邊的有效條件應維持不變。若產品要求保留每個商品並另列有效標記，這個輸出粒度就與有效清單不同，原條件不能照搬。先在紙上寫下每筆分成「來源、是否留下、留下什麼」，再對照推導式，不易把判斷和輸出混在一起。

一次只改一個地方更好診斷。先保持條件，只把左側改成 `sku`，結果的商品數應不變；再恢復元組，改條件，看哪筆不再出現。若同時改輸出與條件，只看畫面變了，很難說是哪條規則造成差異。

若運算式還需要三個條件才能說清楚，先替條件取個名字，再決定要不要縮成一行。可讀與可驗比字數少更重要。

## 常見錯誤

- 看到左邊先寫就以為先換算：篩選先跑；先用原值說清楚門檻。
- 不合格商品仍占一格：把結果設成 0 不是篩選，改用尾端的 `if`。
- 只比對兩份清單長度：長度相同也可能錯留或錯刪；核對代碼與價格。
