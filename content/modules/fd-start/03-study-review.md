## 為什麼要學：今天只有半小時

打開渠成，先別急著把一整條路線加入計畫。如果你只有 30 分鐘，今天的目標可以很小：合上教材，能解釋為什麼茶舖收到 3 張小票，仍可能只成交 2 單。這比「把數據管道的定義看過三次」更容易在明天驗收。這堂只走一遍今天的計畫與明天的複習，不必定下長期課表。

在「今天」找到今日計畫。還沒有計畫時，選「按時間」，點 30 分鐘；想按堂數也可以。專注路線先留「跟著建議」。開始以前看一眼預覽：哪一部分是複習，哪一部分是新課？第一次沒有到期項目是正常的，因為還沒有學過的知識點需要複習。已經在計畫裡的人不必退出本課，也不用重設進度；先用紙模擬，收工時再做最後一步。


## 核心概念：不看答案的十秒鐘

渠成把可以單獨提問的一個想法叫知識點（concept）。「數據工程」太大，不能用一張卡說自己究竟會了什麼；「小票重送時，憑什麼認出是同一單？」大小就合適。現在把第一堂的小票流程圖蓋住，真的停一下，再說出你的答案。能說出「看訂單號，不是看金額」，並舉出兩張同價但不同號的單，就有比眼熟更可靠的證據。

這個動作叫回想練習（retrieval practice）。答案看起來很熟，是辨認；把它從腦裡找出來，才是回想。卡住不代表要把整篇重讀。只翻到區分 A 與 C 的那一段，找出少講的條件，蓋回去，再用自己的話答一次。不要因為剛看完、現在說得很順，就把剛才的遲疑從紀錄裡抹掉。下次隔一段時間再試，看看還能不能答出來。


## 範例：哪一種複習適合明天？

如果今天的困難是忘了名詞，可以在「收工」選明天做「閃卡回想」；如果能背名詞卻說不出怎麼查錯，就選「面試問答」，練習把判斷說成兩句完整的話。開始學 SQL 以後，同一個知識點還可以透過手寫查詢重練。格式是提問方式，不是不同的成績單。系統會記每個知識點的進度，所以今天換一種玩法，不必另外建立一份學習紀錄。

留意「明天怎麼複習？」的數量。選擇格式不會憑空產生題目。若沒有覆蓋到期知識點的 SQL 題，先改用閃卡；沒有到期項目也不用把答對的卡故意評低。預覽是時間估計，不是倒數考試。若今天臨時只剩幾分鐘，可以保住複習而減少新課，明天再接下去。不要為了讓清單全綠，點完自己還沒做過的動手題。


## 常見錯誤

- **看答案時覺得會，蓋住就說不出來** → 把認得當成記得 → 先閉卷說出訂單號與金額的差別，不足處只補一條。
- **選 SQL 手寫卻沒有題目** → 到期知識點沒有 SQL 題覆蓋 → 先改閃卡，不必重設進度。
- **預覽時間超出今晚空檔** → 把新課和複習一起排得太滿 → 保留短複習，拿掉一堂新課。

## 小結：留下一張收工便條

現在自己寫兩行：「明天要問：同價的兩杯茶一定是重送嗎？」「驗收方式：不用看圖，自己說出一個相同訂單號和一個不同訂單號的例子。」先寫問題，把答案留到明天。收工前回想你今天究竟獨立答到了哪一步；若忘了其中一半，把明天的提醒縮到那一半就好。累的時候也能完成的計畫，比排得滿滿卻總是跳過的計畫有用。
