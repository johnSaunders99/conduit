## 成本安全：先用短文字，不付索引或模型費

本堂用 Python 在本機把一段手冊抽取文字切開，不使用模型或向量服務。往雲端放大前先估總片段、重疊、多版本保留和重新索引的費用，限定樣本與清理期限。想像一句「延遲超過兩小時，先核對上游到達時間」被截在逗號；只找到後半句的讀者不知道觸發條件。

切片（chunking）把長文分成可獨立檢索的片段（chunk）。固定長度容易操作，按標題、段落或表格切分則較可能保留有意義的脈絡。重疊（overlap）讓相鄰兩段共享一些內容，可降低邊界漏句的機會，但可能出現幾段幾乎一樣的結果；太長也會把無關內容送給模型。生產環境用的詞元（token）是模型分解文字的單位，不等於漢字數或位元組。

## 先保留可以重現的位置

沿用 `guide-17/v2`。片段鍵記來源、版本、切片設定版本及位置；引用時另存章節或頁碼，以及抽取文字的字元區間。固定 0 起算、左閉右開，`text[start:end]` 即可還原。若先移除換行或合併空格，區間只對應處理後的文字，要保存它或能重現它；不能把這個數字直接當 PDF 原始座標。變更切片規則即使沒有改原文，也要標新版，避免新舊片段混在同一批結果。

## 一段文字切成三段

在 `C:\dev\conduit-lab\ai` 存成 UTF-8 `chunks.py`，執行 `py chunks.py`。步幅＝片段長度減重疊，需要大於 0；最後一段已觸及結尾就停止，避免單靠重疊產生尾巴片段。

```python
text = "延遲超過兩小時，先核對上游到達時間，再通知值班。"
size, overlap = 12, 4
assert 0 <= overlap < size
for start in range(0, len(text), size - overlap):
    end = min(start + size, len(text))
    print(f"guide-17/v2/fixed-{size}-{overlap}/{start}", (start, end), text[start:end])
    if end == len(text):
        break
```

這套規則產生 3 段，後段跨越前段的邊界，但未必保住一句完整的操作指令。替同一問題存一份片段與原句對照，再試按標點或標題切；比較是否找到同時含觸發條件和動作的一段，而不只比段數。下一堂[〈嵌入與向量索引〉](#/lesson/cl-ai-03)會用片段長什麼樣來說明檢索候選的限制。

### 圖表和跨段規則用小評估集比

從手冊挑 3 種提問：只用一句回答、需同時知道條件與操作、以及需要相鄰表格的欄位。每題先記原文的位置和預期證據，再比較兩個切法。若一次召回 3 段卻都來自同一重疊句，就算「找到」，也要記它占掉其他證據的名額。頁碼若由抽取工具另外給出，就保存頁碼與片段範圍；不要把重算片段當作重算整份 PDF 位置的捷徑。

即使選擇固定長度，也先確認欄位標題是否留在每段表格旁。否則模型可能引用一個數字，卻不知道是上限還是實際用量。

## 常見錯誤

- 首尾一再進入同一位置 → 重疊不少於長度 → 要求正步幅。
- 原頁高亮到錯的位置 → 混用字元與原始頁面座標 → 保留抽取版本及座標基準。
- 同句占滿候選 → 重疊造成副本 → 驗召回後調整或依來源去重。
