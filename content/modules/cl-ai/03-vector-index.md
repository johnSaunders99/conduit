## 成本安全：用兩個分量就可以算

本堂用 Python 手填向量，不下載模型、不使用雲端向量索引。日後試用先分別估嵌入生成、索引容量與重建費，限樣本和預算並列好清除測試索引的條件。日報助手問「延遲時先查什麼」，兩個版本的手冊語意都接近，其中一份卻使用已廢止的通知流程。

嵌入向量（embedding）用一串數字來表示文字，以便比較查詢和片段，不用字面完全一樣。向量索引（vector index）幫你快速找接近的向量。近似最近鄰（approximate nearest neighbor，ANN）少查一部分候選以換速度，可能漏掉精確比較會找到的片段；可以先用小集合精確算，作為召回與耗時的基準。查詢與文件需使用相容的表徵，不能只因向量分量數相等就混用模型。

## 用方向比較，但不靠方向核准內容

餘弦相似度（cosine similarity）比較方向：先把對應分量相乘加總，再除以兩個向量的長度乘積。值較高通常表示方向更近，零向量不能用這個公式。下面每條候選的向量都由教材指定，並不是模型計算的分數。Top K 表示取排名最前的 K 筆，與內容獲准、現行或正確無關。

在 `C:\dev\conduit-lab\ai` 存 `vector_demo.py`，執行 `py vector_demo.py`。輸出按分數降序，平手按片段鍵升序，方便重現。

```python
from math import hypot

query = (1, 0)
rows = [
    ("guide-17/v1", False, (5, 0)),
    ("guide-17/v2", True, (4, 3)),
    ("guide-23/v1", True, (0, 1)),
]

def similarity(vector):
    qx, qy = query
    vx, vy = vector
    return (qx * vx + qy * vy) / (hypot(qx, qy) * hypot(vx, vy))

ranked = sorted(rows, key=lambda row: (-similarity(row[2]), row[0]))
for key, active, vector in ranked:
    print(key, active, f"{similarity(vector):.2f}")
```

舊版得 1.00 且排名第一，新版 0.80，另一份 0.00。現行規則的提問應先排除過期版本，且引用仍需回讀原文確認。這裡分數是原始餘弦值；真實服務可能轉換分數，不能直接搬固定門檻。讀者是否有權看到片段，會在下一堂[〈檢索與權限〉](#/lesson/cl-ai-04)加到檢索前的候選條件。

### 先量檢索問題，再決定改哪一層

先用同一批問題保存「應該找哪個來源版本」，並為每個問題保存精確比較的前幾筆。如果正確片段不在精確排名前面，要看是不是切片缺少上下文、文件沒更新，或嵌入本身沒把問題和句子放得夠近；如果精確搜尋找得到而近似找不到，再檢查候選數、過濾位置及索引設定。

還有一個反例值得保留：用語最像的是舊的操作規則，原文卻明說已停用。在小評估集把這題標記為「現行版本必要」，不要讓平均相似分數把過期答覆掩蓋掉。實務上換模型前記版本、分數方式、延遲及估算費用，先在新索引重建驗收，保留可以切回已知可用版本的路徑。

不以單題排名取代整組驗收。

## 常見錯誤

- 高分卻拿到舊答案 → 排名不是時效 → 比對狀態、來源及版本。
- 更換模型後排名全變 → 新舊座標不可隨意混用 → 用相容設定建新索引並驗收再切換。
- 近似搜尋少一筆就判定原文不存在 → 它可能被漏掉 → 對固定小樣本做精確比較。
