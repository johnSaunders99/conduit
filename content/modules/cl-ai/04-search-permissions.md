## 成本安全：先過濾虛構片段，不接公司索引

本堂不用雲端搜尋或模型帳戶，不輸入工作權限或真正的文件。正式做小樣本前先查索引與查詢額度，範圍限於測試群組及內容，最後清掉快取和索引。兩個團隊都問「出報告前要看什麼」，財務指南的相似度最高，但門市讀者不應看見它。

存取控制清單（access control list，ACL）記哪些主體可存取哪份內容。文件衍生的每段需繼承可讀條件，不能因已轉成嵌入就視為公開。授權過濾（authorization filtering）應由伺服器用可信身分產生；模型不是授權元件，使用者在文字裡自稱某群組也不是證據。搜尋端若使用群組欄篩選，必須另有身分驗證及可靠的群組對應。文件沒有可信權限時預設不提供，並送待查。

## 候選進入模型之前就要過界線

對可信讀者，先確定可讀數據範圍，再選其最高分片段。若一開始從所有片段選 Top 1 才遮字，既可能讓未授權片段進模型，也可能把合法的第 2 名永遠排除。實作常在查詢引擎送過濾條件，對交給模型的上下文再做一次防線檢查。快取（cache）若只用問題作鍵，不同讀者會誤用同一份答案；至少依權限範圍隔離，並在權限變更時失效。記錄錯誤時也不要把未授權片段吐回讀者。

## 本機驗兩個角色

在 `C:\dev\conduit-lab\ai` 存 `permissions.py`，執行 `py permissions.py`。分數是固定樣本，角色集合模擬已驗證身分；程式沒有驗證登入。

```python
rows = [
    ("guide-44/v1/0", 0.92, {"finance"}),
    ("guide-17/v2/0", 0.80, {"ops"}),
    ("guide-unknown/v1/0", 0.99, set()),
]

def visible_top(groups):
    visible = [row for row in rows if row[2] & groups]
    ordered = sorted(visible, key=lambda row: (-row[1], row[0]))
    return [row[0] for row in ordered[:1]]

for role, groups in [("ops", {"ops"}), ("finance", {"finance"}), ("guest", set())]:
    print(role, visible_top(groups))
```

門市候選必須是 `guide-17`，財務候選為 `guide-44`，未知權限文件兩者都不可見。這不只是看答案對不對：還要確認模型收到的清單、引用內容和暖快取都沒跨界。下一堂[〈刪除傳播與評估集〉](#/lesson/cl-ai-05)會把同樣的測試用到撤回後的舊副本。

### 別只測同一個索引和同一個讀者

為每個角色保留「可見」與「不可見」的預期來源鍵；懷疑答案混入財務片段時，用同一句問題逐一對照候選、上下文和引用。接著模擬門市權限被撤掉：以前用相同問題填進快取的答案不應再回傳。也要測查不到群組資訊，系統寧可不回答，不能以「沒收到限制」當成「公開」。驗收紀錄只存角色代碼和結果鍵，不抄越權內容。

文件若從共享群組改成私有，索引中的舊權限亦需失效。在下游還沒同步前先拒絕舊索引結果，避免撤權窗口繼續曝光。

## 常見錯誤

- 遮去答案中的標題卻仍洩漏段落 → 授權檢查太晚 → 在候選進上下文前過濾。
- 合法讀者查不到本該看見的結果 → 全庫先取 Top K → 在授權範圍內排名。
- 只在冷快取測試正常 → 共用舊回應沒有被測到 → 以同問題切換身分及撤權重測。
